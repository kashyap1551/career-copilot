## 5.2 Mapping: alias, close spelling, AI pick, review list
**Plain words.** A name from an ad or CV goes down four steps and stops at the first that is sure: (1) exact alias after normalising; (2) close spelling; (3) the AI picks among candidates; (4) otherwise it goes to a review list and stays unlisted (`new:`), so nothing is guessed.
**Code or AI.** Steps 1, 2 and 4 are code. Step 2: edit distance 0 for names of up to 4 letters, 1 for 5 to 8, 2 for 9 or more; two candidates at the same distance means review. Step 3 is the only AI: one batched call per read with the unmatched names, each with up to 5 candidate skills chosen by code; the AI returns a candidate id or "none"; code rejects any answer not in the candidate list. New prompt, new schema, its own fingerprint (the ad and CV fingerprints stay).
**Hand-worked cases first.** Exact alias; German alias; "Pyhton" gives python; "Tablau" gives tableau; "Exel" (4 letters) is not corrected; "Java Script" gives javascript but never java; a tie goes to review; a candidate not in the list is rejected; an AI "none" gives `new:`; an AI answer for a name that was not asked is ignored; the same name twice in one reading maps once; the order of steps (an exact alias is never overruled by the AI).
**Check and measure.** SPRINT: wrong mappings stay under 5% on the test ads. Rule 6 says counts, so: a label file lists, for every distinct name seen on the test ads and CVs, the expected id or "none"; the script prints mapped right, **wrong**, review and correctly-none, and the limit as a count (5% of the number of names, worked out once the capture run gives it; at 250 names that is 12). Two further pass lines: wrong merges of the "must not merge" set 0, and review at most a count we fix before the run. Stages 1 and 2 are measured first, with no AI; stage 3 is built only if they leave too many unmatched (decision 6).
**Risks.** Stage 3 sends skill names to Groq (new data flow, but names only: no quotes, no CV lines, no ad text; names from a CV can still be unusual). It adds a call per read (one batch, about 1,500 tokens) and latency. Danger of a second 3.3: a prompt tuned on the test names; so one prompt, one run to calibrate, then two counted runs, as in 4.2, with the holdout names as the out-of-sample check. A wrong merge is worse than a miss, so any doubt goes to review. The review list needs a place on the page (names only) and a process: you or I add the alias to the vocabulary; no admin screen.

## 5.3 Store each reading under a hash of the text
**Plain words.** Pasting the same ad again shows the same reading with no second AI call; the same for the CV.
**Code or AI.** All code. Key: SHA-256 (the browser's built-in `crypto.subtle`; no new package) of the text with line endings unified, whitespace collapsed and the ends trimmed (case kept, because quotes are checked against the original text), plus a `READING_VERSION` that changes with the prompt, schema or model. The CV key hashes the numbered, redacted lines. Stored: the checked reading (not the text).
**Hand-worked cases first.** Same text twice: one call, equal results. Extra spaces, a trailing newline or CRLF: same key. One word changed: new key. Empty text: no key, no call. A failed call (429, 5xx, wrong shape) is never stored. A different READING_VERSION: a miss. Capacity 20 readings, oldest out. A test that fails when INSTRUCTIONS or the schema changes without bumping the version (it pins their hash).
**Check and measure.** SPRINT: pasting the same ad twice makes one AI call. Measured with a fake fetch that counts calls (no real call), and once by hand on the live link.
**Risks.** Where it lives (decision 7): page memory now, so a reload clears it and nothing is stored on a device or server; IndexedDB comes with 6.1 behind the same small interface, with consent and delete on 9.3. A stale reading after a prompt change is what READING_VERSION guards. Nothing new is sent anywhere.

## 5.2 stage 2 rules and outcome definitions (fixed before any measure)
Written 2026-11-16, before any 5.2 code and before any 5.2 measure. They refine the stage 2 and pass-line paragraphs above; where they differ (the shorter string sets the allowance; a swap counts 1; a name flagged as not-a-skill by mistake is wrong), these win.

**Which names count.** The 5.2 pass lines use the **fresh set only** for L. The holdout (ad-09, ad-10) is printed next to it, **not pooled**, because its counts were seen on 2026-11-16. The fresh set is measured once. Stage 2 is **not wired** into the live path (`fromAd`, `fromCv`, the routes, the page) until the fresh-set measure passes.

**Close spelling (stage 2), run only when stage 1 finds nothing.**
- **Strings compared.** The name and every target string are folded like stage 1 (lowercase; accents and umlauts folded, ß as ss; level and filler words and a trailing version removed), then spaces, hyphens and dots are dropped. Targets are every name, German name and alias of every skill.
- **Never a target:** an undecided alias, any `exactOnly` entry (R, C, Go), and the not-a-skill phrases. (A wrong drop hides a real skill; a miss costs one line.)
- **Distance** counts insert, delete, replace, and swapping two neighbouring letters, each as 1.
- **Allowance** comes from the **shorter** of the two folded strings: up to 4 letters 0, 5 to 8 letters 1, 9 or more letters 2.
- **Choosing.** Take the smallest distance per skill id. The name maps only if exactly one skill id has the overall smallest distance and that distance is within the allowance. Two or more ids tied at the smallest distance, with at least one within the allowance: no mapping ("tie", goes to the review list). One skill reached through several of its own strings at the same distance is not a tie.
- **Stage 1 (exact, three tries) always runs first and wins.**
- **Result of the mapper (`mapName`):** `{how:"exact", id, try}` or `{how:"close", id, distance, via:<the alias or name that matched>}` or `{how:"tie", ids}` or `{how:"none"}`.
- **Live order is kept in the measure:** a name on the not-a-skill list is flagged before anything is mapped (as `fromAd` does); only then `mapName`.

**Outcome definitions for the measure.** Each labelled name has a label: a skill id, "none" (should stay unlisted), or "not-a-skill".
- **RIGHT:** mapped to the labelled id; or unlisted when the label is "none"; or flagged not-a-skill when the label is "not-a-skill".
- **WRONG:** mapped to a skill id that is not the label (this includes any label "none" or "not-a-skill" that got a skill id: "wrong merges"); or flagged not-a-skill when the label is a skill id or "none" ("wrongly flagged").
- **NOT MAPPED:** a tie or none when the label is a skill id.
- A name labelled "not-a-skill" that is neither flagged nor mapped is counted apart ("trait not flagged"); it is in |L| and in no line.
- **M** = the names whose label is a skill id; **right_M** = those mapped to the right id.
- **Recall line:** `4 x right_M >= 3 x |M|`; with |M| = 0 the line is "not measurable" and counts as NOT passed.
- **Wrong line:** `wrong <= floor(5 x |L| / 100)` (|L| = 19 allows 0, |L| = 20 allows 1).
- **Must-not-merge line:** any name mapped to the other member of a must-not-merge group (the groups of docs/VOCAB-REVIEW.md, kept as data in `lib/vocab/mustNotMerge.ts`, plus the word "shift" which must not become Swift) counts; the line is 0.
- **The check passes only if all three lines pass.**

**Tools (offline, no AI call).** `npm run vocab-pairs` lists the pairs of different skills whose strings are within the allowance of each other (vocabulary only). `npm run map-measure -- <labels.json> ...` maps the labelled names and prints counts only; names of wrong and not-mapped items go to the gitignored `eval-runs/map-measure-detail.json`; each run is logged (set, date, vocabulary hash) in `eval-runs/map-measure-log.txt`, and a second measure of a set with a different vocabulary hash prints "REPEAT: second look, not the one-shot measure".

### Changes before any measure, 2026-11-16
Three rule changes, made BEFORE any 5.2 measure and none taken from an ad name or a measure result. Where they differ from the paragraphs above, **these win** (the allowance bands "up to 4 letters 0, 5 to 8 letters 1" above are replaced by the first change).
1. **Allowance by the shorter folded string: up to 5 letters 0, 6 to 8 letters 1, 9 or more 2.** Reason: the word "shift" mapped to Swift (found through the owner's own must-not-merge list); short names have the most ordinary-word and real-skill neighbours (Flash and Flask are two real tools one letter apart).
